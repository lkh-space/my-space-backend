# 프로젝트 문서화 (Documentation)

이 디렉토리는 **My Space Backend (`my-space-backend`)** 프로젝트의 설계 방향, 아키텍처 의사결정, 비즈니스 기능 규격 및 API 요구사항 명세를 체계적으로 기록하고 관리하는 공간입니다.

본 프로젝트는 코드 작성에 앞서 명세를 먼저 정의하고 검증하는 **스펙 주도 개발(SDD, Spec-Driven Development)** 프로세스를 엄격히 준수합니다.

---

## 디렉토리 구조 (Structure)

| 경로 | 용도 | 표준 포맷 | 설명 |
| :--- | :--- | :--- | :--- |
| [`adr/`](./adr/) | 아키텍처 의사결정 기록 | [MADR 4.0.0](https://adr.github.io/madr/) | 프레임워크 전환, 인증 체계, 인프라 등 번복하기 어렵고 중요한 기술적 합의 기록 |
| [`specs/`](./specs/) | 기능 및 API 요구사항 명세 | SDD 스펙 명세 양식 | 개별 유틸리티 기능(도메인) 설계, 데이터 모델 및 API 인터페이스 세부 스펙 명세 |

---

## 문서화 규칙 (Conventions)

1. **언어 (Language)**:
   - 모든 문서는 **한국어(한글)** 작성을 원칙으로 합니다. 불필요한 한영 병기나 복잡한 외래어 표기는 지양합니다.
2. **파일명 (File naming)**:
   - 모든 문서는 소문자 하이픈 조합의 `kebab-case.md` 형식으로 명명합니다.
   - 아키텍처 의사결정 기록(ADR)은 4자리 순차 번호 접두사를 부여합니다 (예: `0001-pino-structured-logging.md`).
3. **필수 프론트매터 (Front-matter)**:
   - 모든 문서(ADR 및 Spec)는 최상단에 YAML 프론트매터를 선언하여 현재 문서의 진행 및 검토 상태(`status`)를 명확히 관리합니다.
